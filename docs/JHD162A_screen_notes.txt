================================================================================
JHD 162A LCD — Notes for LightSensor v2
================================================================================

OVERVIEW
--------
JHD 162A = 16x2 character LCD (16 columns, 2 rows) built around the HD44780
controller — the standard chip used by nearly every character LCD.

- Character-based, NOT pixel-based. You send a byte (e.g. 0x41) and it draws
  the matching font character ("A"). Font is in the controller's ROM.
- CGRAM: room for up to 8 user-defined 5x8 custom characters (useful later for
  a bar graph or a "saturated" icon).
- Two register types selected by the RS pin:
    RS=0 -> command register (clear, move cursor, configure)
    RS=1 -> data register (characters to show)
- Parallel interface: 8 data pins D0-D7, but supports 4-BIT MODE using only
  D4-D7 (each byte sent as two nibbles). 4-bit mode is what we use — saves 4
  GPIO pins. Total pins needed: 6 (RS, E, D4, D5, D6, D7).


JHD 162A 16-PIN LAYOUT
----------------------
 Pin  Name  Purpose
  1   VSS   GND
  2   VDD   +5V (logic + controller)
  3   V0    Contrast — wiper of a 10k pot between VDD and GND
  4   RS    Register select (command/data)
  5   RW    Read/Write — TIE TO GND (write-only)
  6   E     Enable — pulses to latch each transfer
  7-10 D0-D3  Data — UNUSED in 4-bit mode
 11-14 D4-D7  Data — the 4 we wire
 15   A     Backlight anode (+5V, often via ~220 ohm resistor)
 16   K     Backlight cathode (GND)


TWO GOTCHAS FOR ESP32 (3.3V logic, 5V LCD)
------------------------------------------
1. RW MUST GO TO GND. Never let the LCD drive a pin back into the ESP32 — the
   HD44780 powered at 5V would put 5V on a 3.3V GPIO and damage it. Write-only
   mode avoids this entirely.

2. 3.3V signals into a 5V LCD. HD44780 logic-HIGH threshold is ~0.7 x VDD
   ~= 3.5V at 5V supply, so 3.3V is technically marginal. Most work fine. If
   flaky, power the LCD LOGIC (pin 2) from 3.3V instead of 5V — then 3.3V
   signals are full-scale. Backlight (pin 15) can still take 5V.

3. CONTRAST POT IS ESSENTIAL. Without V0 set correctly you'll see either
   nothing or just black boxes on the top row (and wrongly assume it's broken).
   Use a 10k potentiometer: pot ends to VDD and GND, wiper to V0. Start with
   the wiper near the GND end.


WIRING (4-bit mode, ESP32-C3 SuperMini)
---------------------------------------
I2C (ADS1115) is on GPIO8 / GPIO10, so keep the LCD off those.

 LCD pin    ->  ESP32-C3
 VSS (1)    ->  GND
 VDD (2)    ->  5V (or 3.3V if signals are flaky)
 V0  (3)    ->  pot wiper (pot ends: VDD <-> GND)
 RS  (4)    ->  GPIO2
 RW  (5)    ->  GND
 E   (6)    ->  GPIO3
 D4  (11)   ->  GPIO4
 D5  (12)   ->  GPIO5
 D6  (13)   ->  GPIO6
 D7  (14)   ->  GPIO7
 A   (15)   ->  5V (through ~220 ohm if no onboard resistor)
 K   (16)   ->  GND


HOW TO BEGIN (test plan)
------------------------
- ESP32 Arduino core ships with the LiquidCrystal library (parallel HD44780).
  No install needed.
- Steps:
   1. Wire per the table above — ESPECIALLY the contrast pot.
   2. Minimal test sketch in a new lcd_test/ dir (keep it separate from the
      sensor firmware):
         LiquidCrystal lcd(RS, E, D4, D5, D6, D7);   // pins 2,3,4,5,6,7
      print "Hello" + a counter.
   3. Add a `just` command to flash it.
   4. Once "Hello" shows, evolve toward displaying the actual light reading.

- Open question: confirm a 10k potentiometer is on hand for contrast — that's
  the part that most commonly trips people up.

GPIO pin budget (ESP32-C3 SuperMini): 13 usable GPIOs total. Need 2 (I2C) +
6 (LCD 4-bit) = 8. Plenty of headroom. Avoid GPIO9 (boot button).
